## 接口与保护

- 固定 `cs_army_set_troops`（902）：`army_id, hero_id_list, hero_troop_list, cons_index`。
- `hero_troop_list` 是每将补完后的目标总兵力，不是增加数量。客户端逐将上限决定目标，调用者不能自由填写兵力或协议。
- 普通兵源由 `army.status.is_person_guard=false` 且 `person_guard_index=0` 确认，对应 `cons_index=1`。武将的 `is_imperial_guard_*` 不能用于判断亲卫预备兵；实测亲卫队这两个武将标记也可能均为 false。
- 先检查阶段、所属城和驻点，再读取兵力；交战、战平、行军及未知阶段不进入兵力读取。
- 队伍编制、兵力、容量、兵源、伤兵恢复和征兵队列在发送前重新检查。只发送一次；成功必须同时取得目标队伍 1091 通知、902 成功响应和实际逐将满兵。
- 原生回调内调用接口可能观察不到自己的出站编码。独立测试进程复现了直接/间接调用均漏计、正常来源调用可以计数。独立原生调用次数必须为 1；出现其他线程/外部 902、重复编码或回执不明仍停止。
- `.state/replenish/commands.sqlite3` 在发送前持久化日志。相同 request_id 返回原结果；未知命令同时阻止换 request_id 重发。正在/曾经打野且交战或命令未结算的队伍被排除。
- 独立 CLI 与诊断脚本需要持有生产 worker 的目录锁，不能与运行中的 agent 并发执行。日常使用 DSH 工具。
- 单独的 `.state/replenish-api-validation.json` 绑定角色、客户端版本、实现摘要和事故记录。原打野隔离不会被解除；新原生异常、清理失败或未知结果撤销补兵验证。
