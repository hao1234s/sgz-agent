# 通用战斗评估

适用于任意武将组合。阵容、战法、兵种、目标和门槛均来自当前任务或观测，不内置某个队名的胜负结论。先读取 [评估模型、输入与玩家来源](references/model.md)，用只读工具 `sgz_assess_combat` 做可复核计算。

## 阶段优先

已行军、交战、战平待续战或连续守军未打完时，只等待整次交战最终结算。不要为评估刷新队伍、扫描地图、读取兵力或战报，也不要因偶然可见的残兵触发回城。阶段不明按 `unknown` 处理；工具此时只返回 `wait`。用户明确要求撤回是另一条指令。

战前或已确认整次交战结束后才取新数据。工具只计算传入值，不读取游戏、不采集战报、不派兵，也不会替调用者确认输入真实性。没有实时读取能力时说明缺口，不拿旧截图当当前状态。

## 四项判断

1. **输出**：逐将分析实际可出战兵力和预计到达士气。兵力影响非线性；低于 100 的士气按已核验规则降低自身伤害。不要把总兵力乘士气当成有效战力，也不要把士气损失称为受到伤害的减免。伤害角色、战法倍率/发动率、等级与攻防属性、克制、控制和爆发回合影响能否及时击败守军。
2. **存活**：列每将兵力及编制占比，单独检查主将、主要输出和治疗武将。相同总兵力不同分配不能等价；总兵力高不能掩盖主将濒危。兵力占比只是兵池，承伤还受减伤、治疗、控制、援护与对方集火影响。未知项保留未知，不自定万能权重合成战力分数。
3. **连续作战**：核实目标各队守军与整次结算规则，评估全程耗损和续航；首队胜利、八回合结束、战平及中途撤回都不算完整击杀。一次观察到的守军数不能写成所有目标的常量。
4. **依据**：区分当前数据、机制计算、社区近似、可比完整战报和主观判断。完整战报才支持实际胜负经验；同名阵容、跨赛季 PvP 战报、不同守军和剪辑高光不能直接迁移。

## 工具输入与决策

- `heroes`：每将稳定标识、是否主将、当前可出战兵力、当前编制上限；不把预备兵、伤兵或容量当兵力。`arrival_morale` 是预计到达值；`observation_age_seconds` 反映输入中最旧的当前状态。`morale_rule_verified` 只在确认当前模式使用该基础规则时填 true。
- `min_total_troops` 来自任务政策。通用工具默认 0，无通用的 20000 门槛；当前巨戟士讨伐 skill 明确传 20000。主将/武将不可出战须另查；工具不能仅靠兵数发现重伤或征兵状态。
- `context` 标识版本/赛季/模式、完整我方配置及全部守军配置；未知就不填，不能用队名或“巨戟士”替代配置指纹。`reports` 使用来源明确、未重复的完整交战记录；只按同一配置比较，不把更换阵容前的样本当作当前战绩。
- `supported_attempt`：存在至少 3 次同条件完整胜利，当前每将兵力与士气都不差于各自那一次样本，且没有冲突败绩；这是保守经验策略，**不是必胜或胜率**。还需检查体力、消耗、位置、目标时效和任务授权。
- `high_risk`：同配置在不弱于当前兵力/士气的条件下有完整败绩；先改善准备再评估。`replenish` / `not_ready`：按任务规则回补或恢复；`wait`：等待，不检测兵力。
- `insufficient_evidence`：指出具体缺口，展示能计算的士气折扣和逐将兵力情况，不编造百分比。区分“当前数据缺失”和“尚无同配置战报”。缺失当前数据先补齐；没有历史样本不等于必败，也不构成自动追加试打的授权。只有任务已允许的试打可积累首批样本，明确其不确定性，次数仍受原任务约束。

低于 100 士气并非统一禁战线。若同配置低士气完整战报确实支持当前条件，可进入其余战前检查；缺少依据时优先恢复/调动至预计到达至少 100，再评估。不要跨“更多兵但更低士气”等互有优劣条件强行套用样本。

## 结果与学习

输出：阶段、各将兵力/主将情况、预计到达士气及伤害折扣、守军队数、输出/存活/续航依据、可比战报数、结论、未知项与下一步。比较两个方案时明确谁的兵池更大、谁的输出折扣更小、补兵/调动/恢复耗时；没有足够数据就不强排胜率。

整次交战结束后记录出发配置、每将初始兵力、到达士气、全部守军、最终结果、最终每将兵力、战报来源和规则版本。战平/中断单独记录，不纳入完整胜负；换战法、升级、变更兵种/科技/装备/主将或守军后分组。工具目前按传入战报计算，尚不自动采集或持久化战报。
