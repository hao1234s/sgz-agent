# 巨戟士讨伐

用户要求“所有队伍开始打野”或多队持续讨伐时，转用 `sgz-multi-army-hunt` 的持久化调度和补满策略；本文件的一次性默认适用于单次任务。战中等待约束按队伍隔离，不能因一队战平冻结其他闲置队伍。

只用用户指定队伍打巨戟士。先判断所处阶段，再决定能否检查兵力：**交战、战平倒计时和同一目标的连续守军战斗都属于战斗中；整次交战最终结束后才检查兵力并决定回补。** 技能加载不等于已下达游戏命令。

战前加载 `sgz-combat-assessment`，用 `sgz_assess_combat` 对用户指定的任意编制做兵力、士气和完整守军评估；本 skill 只提供巨戟士目标规则和当前任务的 20000 回补门槛，不保存某支阵容的胜负结论。需要解释战斗、伤兵或营帐机制时，读取 [机制与来源](references/mechanics.md)。当前界面、已验证接口与赛季规则决定实际数值。

## 本项目已确定的规则

| 条件 | 动作 |
|---|---|
| 交战、战平待续战、连续守军尚未打完 | 等待；不检索地图/队伍、不打开兵力或战报页、不因兵力减少回城 |
| 已出征，但不能确认整次交战结束 | 保持等待状态；不能把超时、单份战报或出现回城按钮当作结束 |
| 出征前或整次交战结束后，可出战兵力 `< 20000` | 不发起新的讨伐；返回已确认可补兵的本人城池或可用营帐补兵 |
| 出征前可出战兵力 `>= 20000` | 进入士气、体力、目标与费用检查；20000 本身允许，不代表必胜 |
| 战前各项检查通过，目标是巨戟士，出现“兵力悬殊／坚持出征” | 用户已授权自动坚持出征，无需重复确认同类风险弹窗 |
| 尚未出征，身份、目标、兵力或操作结果不明 | 只核验缺失信息，不提交新的出征命令 |

阈值指这支队伍当前可出战兵力，不是三支敌军的总兵力、预备兵、编制容量或含伤兵的合计。伤兵是否已经排除要按页面字段含义确认，不重复扣减。

用户当前只授权指定队伍和指定目标类型；从当前任务解析队伍标识，不默认选某位武将。次数采用当前任务的明确数量，未指定次数按一次处理。一次出征后不自动重试失败目标；战平的自动续战属于同一次出征，不是重试。最终战败时停止追加攻击，完成必要回补并报告；结果不明则保持等待，不自行撤回。完成最后一个目标后，若低于阈值仍完成回补，不再追加目标。

## 执行前核对

1. 若接手的是已出征任务，先按已有阶段和非兵力状态标记判断是否仍在战斗；未能确认结束就进入等待，不先刷新 roster 或点开队伍。确认没有未完成交战后，才用 `sgz_game_status` 取得 world，通过 `sgz_query_roster`、必要时 `sgz_refresh_roster` 核对队伍、所属城池、实际位置和状态。同名队伍核对城池与编制，当前位置不能用目的地代替。
2. 记录队伍当前驻点、出发点及预期返回点；所属主城不一定是本次回城目的地。征兵、调动、返回、重伤恢复中的队伍先等待完成，不下达冲突命令。
3. 读取最新可出战兵力、各武将可用状态、体力、士气及上限。现有 roster 不含兵力，不能用旧截图、编制容量或预备兵代替；需要已验证的队伍状态工具或当前游戏画面。兵力不足先回补；主将不可出战或队伍未准备好时不出征。
4. 目标详情确认后，用通用评估工具传入各将兵力、预计到达士气、已知配置与完整战报，`min_total_troops=20000`。单独评估主将、输出和续航，覆盖全部守军。依据不足时明确缺口，不把“超过20000”或近似伤害指数解释为能赢；没有历史战报并不自动授权额外试打，已有一次讨伐授权仍只限该一次。

## 士气与调动

- 优先准备到预计到达士气至少 100；这是降低战损的策略，不是游戏禁战线。若通用评估中的同配置完整战报支持当前低士气条件，可以继续其余战前检查。不能用更多总兵力简单抵消士气折扣；允许坚持出征不等于允许忽略未知状态。
- 优先使用出征页的预计到达士气、实际距离和耗时。缺少预计值时，只有确认当前赛季的行军扣减规则后才能估算并标记为估算；不能用坐标直线距离冒充实际消耗，也不能把“当前120”当作“到达120”。未知时先补齐信息。
- 到达士气不足时，在出征前比较现有可用营帐/驻点调动方案和安全停留恢复方案。调动、普通行军、驻守不是同一命令；调动到营帐后重新确认驻点、士气与下一段路程。默认不新建营帐、不派另一队铺路、不消费道具加速。
- 恢复时长以当前提示为准，不把旧攻略的恢复速度和调动加速倍率写死。体力按实际出征消耗核对，等待自然恢复；不把士气和体力混为一项。

## 查找与出征

- 巨戟士属于普通地图贼寇。当前已核验客户端中 `use_code=1, conf_id=10` 对应十级巨戟士；单看 conf_id=10 不够，个人蛮族配置也会使用这个编号。以当前版本校验和实时详情为准。
- 仅在战前检索。`sgz_search_map` 可提供已有候选，必须检查时效和覆盖。当前通用 `sgz_scan_region` 只覆盖资源和个人 NPC，空列表不能证明附近没有巨戟士。需要已验证的区域贼寇查询；接口不能覆盖时说明能力缺口，只有用户接受 UI 采集才用画面核对，不静默改成逐格点击。
- 用户明确要求最近目标时，覆盖不足应继续核验；不能仅改称“候选中最近”就直接出征。
- 按指定队伍实际位置比较目标距离，出征页的游戏距离或行军时间优先；坐标直线距离只作筛选，不能当成游戏行军距离。目标被击败、消失或改变时重新查找巨戟士，不替换成蛮族或其他目标。
- 用 `sgz_inspect_target` 或当前可用的游戏 UI 查看目标详情。核对目标名、坐标、类型、守军队数与已知兵种；巨戟士名称不代表固定兵种，也不代表只打一队。不能直接侦查时保留未知，不为探路额外派队或消耗策书，不擅改指定队伍的武将、战法、装备和兵种。
- 最终确认队伍、可出战兵力、预计到达士气、体力、策书和返回点。普通讨伐的正常消耗包含在本次授权内；不购买策书、不用讨贼令、不替换为协讨/扫荡。保持自动回城，并确认它指向哪座城或营帐。
- 满足上述条件才执行一次讨伐，并按已授权规则处理“坚持出征”。随后核验队伍已进入行军状态、目的地与目标一致。提交超时或结果未知时先查状态，不重发、不另选目标。

## 出征后的等待

- 确认行军后进入等待，冻结本次讨伐的地图扫描、目标搜索、队伍刷新、兵力检查和重新选目标。战平倒计时、刚击败其中一队守军仍保持此状态；即使画面偶然露出不足 20000 的兵力，也不触发回城。
- 优先等待已有行军/交战状态的完成通知；没有通知能力时，只在预计状态变化时查看非兵力的状态文字或结束提示，不展开队伍，不打开战报，不调用地图或 roster 检索工具。倒计时到零只是复核时点，不是完成证据；观察间隔不需要逐秒轮询。
- 只有确认该目标的整次交战已最终胜利或失败，且队伍已退出交战/战平续战状态、没有待打的连续守军，才进入战后检查。单份胜利/战平战报、八回合结束、回城按钮可点、画面暂时不动，都不能单独证明完成。
- 断线、观察超时、无法确认结束时，保留队伍和目标信息并报告“仍待确认”；停止新的命令，不用回城来消除不确定性。用户明确另行要求撤回时才处理该新指令。

例如：战平 `1:38`，旁边露出 `14216` 兵和“回城”按钮 → 继续等自动续战；最终结果和脱离交战均确认后 → 再读当前兵力，低于 20000 才走回补。

## 战后与回补

1. 确认整次交战结束后，读取最终战报与当前可出战兵力，记录胜负、伤兵及剩余次数。击败一队守军不等于击败整个巨戟士；最终战败不计击杀，也不自动重试。
2. 低于 20000 时进入回补。已经自动返回就等待到达，不重复撤退或中途改道；仍在野外时选择已核实可用的补兵点。达到阈值（含恰好 20000）且任务已完成时，等原定自动返回并记录结果，不擅自追加补兵或目标。
3. 确认补兵点允许这支队伍进入、容量可用且具备实际征兵能力。附近友军营帐、同盟城池或地图名称不能单独证明可用；无法确认时选已知可补兵的本人城池。区分“回城”（回当前出发驻点）和“调动”（转移至另一可用驻点），操作前核对实际目的地。
4. 比较可用地点的行程、伤兵恢复、征兵排队与耗时、普通资源/铜币消耗。营帐更近不一定补得更快；有明确时间与成本优势时选择主城，否则使用已确认的营帐。任务还有次数时计入后续出征路程；不能假设主城队伍调到分城便能使用其征兵功能。
5. 到达后先核验同一队伍已入城/入营、伤兵恢复后的实际可出战兵力，再算缺口。已进入回补流程的队伍，使用普通征兵补到当前编制可用上限；恢复伤兵不等于完成征兵，不重复把伤兵数加到界面总兵力。检查可用预备兵、资源、队列和预计完成时间，已有征兵就等待，不重复提交。
6. 等待征兵和重伤等不可出战状态结束，重新核验实际兵力、士气及体力，才记为“补兵完成”。资源不足或能力不明时报告停在哪一步；不购买加速、不消费额外道具、不改编武将。只有任务尚有明确剩余次数、上一目标最终成功且再次通过战前检查，才继续。

## 当前工具边界

`sgz_*` 现有工具支持观察、检索及传入数据的通用战前评估，没有派兵、撤退或补兵动作接口；`sgz_pause_task` 只暂停 agent 任务，不能撤回已出发的游戏队伍。不得编造工具名称、用任意 Lua/网络发送入口绕过工具范围，或把诊断脚本当成稳定执行工具。

若当前宿主另有已授权的游戏 UI 控制能力，可逐屏观察并执行上述操作，每个关键动作后核验；没有动作能力时，准确报告缺失的执行接口，保留目标与队伍信息。创建此 skill 本身不代表 DSH 已具备无人值守讨伐与补兵能力。

## 结果记录

记录 world、队伍标识、目标坐标与类型、出发及结算兵力、战报结果、返回目的地、补兵状态、已完成/剩余次数和下一步。明确区分“候选已找到”“已出征”“战斗已结算”“已到达”“正在补兵”和“补兵完成”。

## 可选能力

先确认当前注册的工具。仅当 `sgz_assess_combat` 可用时加载并调用计算技能；仅当 `sgz_knowledge_search` 可用时检索知识。对应能力关闭时明确说明缺口，不编造计算或检索结果，不自行启用模块。
