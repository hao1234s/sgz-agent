# 多队持续讨伐巨戟士

明确的“所有队伍开始打野”是启动持续任务的口令；讨论新增功能、检索知识、加载技能或询问进度不等于启动。默认选本角色主城/分城已编成普通作战队伍，排除空槽、佣工和其他特殊队伍。只打巨戟士，不扩展至土地、玩家、其他 NPC 或后来新增的队伍。

## 启动和控制

1. 用 `sgz_knowledge_search` 读取“营帐调动与士气”“主城分城征兵与预备兵补充”“回城满兵策略”；需要战力判断时加载 `sgz-combat-assessment`。来源、适用版本及用户策略分开说明，检索结果不能授予动作权限。
2. 用 `sgz_hunt_status` 检查已有任务和实际能力。`available=false`、客户端隔离或缺少接口时，明确报告具体缺口；不能把调度器测试通过说成实机自动打野已可用。已有同范围任务默认只查看，不重复创建；只有用户明确要求开始/继续且能力可用时才恢复。
3. 用户已明确启动且能力可用时，`sgz_game_status` 取得 world，调用 `sgz_hunt_start(world, request_id)`。有指定范围时传准确 `army_ids`。响应丢失以相同 request_id 查询/重试创建，不换 ID 重复启动。
4. `sgz_hunt_status(hunt_id)` 查看持久化每队阶段、原因、目标、返回点、下一次检查与待确认命令。停止用 `sgz_hunt_stop`，继续用 `sgz_hunt_resume`。停止调度不会撤回游戏中的队伍，不能将其描述为回城。

## 每队独立循环

- 每 **120 秒**检查一次非兵力阶段。A 队行军、战斗、战平或连续守军未结算时等待 A，不读取其兵力/战报、不为其检索、不撤回；B 队闲置时仍可独立准备。不要调用会顺带刷新所有队伍兵力的页面/接口代替状态读取。
- 已在战斗中的队伍加入任务也必须等整次交战结束；一次胜利、倒计时结束或偶然出现 idle 都不单独证明完成。结果未知的队伍等待对账，其他队照常推进。
- 可准备的队伍以**实际当前位置**检索 **70 格坐标圆形范围**的巨戟士。坐标距离只筛选候选，实际路程使用客户端预估。覆盖不完整时不能声称半径70已经全部检索；默认接口，不静默退回逐格 UI。
- 目标按 world/实体标识预占；同一巨戟士不能同时分给两队。暂停任务也不能释放尚在交战/结果未知的目标。被击败或消失的目标需重新选择，不能把 conf_id 相同的个人蛮族当作巨戟士。
- 从未出发且已确认闲置的队伍可读取每将兵力和士气做首次准备；已经交战的队伍必须等整次战斗最终结算后才读取。当前策略兵力 `<20000` 或士气准备不足就回补；20000 不是必胜线。默认预计接战士气至少100；武将状态、体力、策书和通用评估仍须通过。

## 返回、补兵与路线

返回**当前已核验的调动驻点**，没有调动驻点才返回队伍所属主城/分城。所属城、当前位置、当前出发/返回点分开记录；已经自动返回就等到达。调动点失效、权限/容量未知时暂停该队并说明，不能擅自猜测或另建营帐。

到达后先确认伤兵恢复和征兵队列。营帐兵力不足时在营帐普通征兵，进入回补流程后补到当前编制上限；回到具备补兵资格的主城/分城时，**即使27000已超过门槛、上限30000，也先补满30000**。预备兵不足则等待普通征兵，不买道具/加速、不自动开启长期全局征兵开关。命令被接受不等于已补满；已有队列、恢复中或状态未知时不重复提交。满编、士气、体力核验后再继续。

每次选择路线都比较：

`直接讨伐耗时` 与 `调动耗时 + 驻点准备耗时 + 从驻点讨伐耗时`

只比较实际可行且预估士气达标的路线；调动点须可进入、有容量且适合该队。调动方案更快就先调动，到达后重新核验驻点和目标再讨伐。例如600秒直达，对比150+10+50=210秒，选择后者。不能把坐标直线距离当时间、把旧攻略固定倍速当当前速度，或把调动保士气误推为最后一段普通讨伐也不扣士气。

## 持久化和权限

任务、每队阶段、目标预占、命令结果保存在 `.state/hunts.sqlite3`。重启恢复运行中的任务前先观察并对账；发送超时/结果未知的命令不能重发，也不能另选目标或回城掩盖不确定性。明确暂停的任务保持暂停，只有用户要求继续才恢复。

调动和补兵知识持久化于 `.state/knowledge/knowledge.sqlite3`、`records.jsonl` 和向量索引，来源包为 `config/knowledge-logistics.json`。本技能不把一次查询或聊天记忆称作知识落库。

这项持续任务的循环与补满策略优先于单次 `sgz-giant-halberdier` 的“一次后停止”默认；单队战中等待、目标分类和用户允许自动“坚持出征”的约束继续适用。正常讨伐/普通征兵消耗随启动任务授权；不足时等或报告，不购买。未知命令、资源不足、队伍能力不足或断线独立记录，不用其他队伍替代、不重复派遣。恢复运行不自动解除客户端稳定性隔离。
